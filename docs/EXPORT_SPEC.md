# التصدير والتسليم — الماستر ≠ ملف النشر

> **الخلاصة:** عندنا **ملفان مختلفان بنيوياً**: ماستر للأرشيف على Drive، وملف منصّة للرفع. الخلط بينهما هو سبب «الفيديو تقيل» أو «الصورة بتبوكسل بعد الرفع».
> المرجع: `remotion.config.ts` · `docs/RUNBOOK.md` · فحوص §3.

---

## 1) سياستان لا سياسة واحدة

| | **الماستر** (أرشيف) | **ملف المنصّة** (نشر) |
|---|---|---|
| الوجهة | Drive — ملف الحلقة | YouTube / Reels / Shorts |
| الدقة | 4K إن وُجد (3840×2160) | 1080p (أو 2160p للطويل) |
| `crf` | **18** (الحالي) — الجودة أهم من الحجم | **21** |
| `profile` | h264 high · yuv420p | h264 high · yuv420p |
| `+faststart` | لا يهم | **إلزامي** (يبدأ التشغيل قبل اكتمال التحميل) |
| `keyint` | افتراضي | **60** (`min-keyint=30`) — سكرَب سلس |
| `maxrate` | — | 12M / bufsize 24M (1080p) |
| الصوت | AAC 192k 48k | AAC 192k 48k |

**لماذا crf 21 للنشر وليس 18؟** لأن 18 يزيد الحجم ~2× لفارق حدة لا تراه العين بعد ترميز المنصة (المنصة تعيد الترميز أصلاً). عندنا قياس واحد موثّق من منظومة أخرى (18 ⇒ 32.4MB/حدة 0.851 · 21 ⇒ 14.8MB/0.868) — **مقيس على محتوى مختلف**، لذلك يُعامَل كـ«مفترض» حتى نقيسه على محتوانا (§4).

## 2) أمر التصدير

**الماستر (كما هو الآن):**
```bash
npm run render:golden        # --crf=18، concurrency=1
```

**ملف المنصّة (من الماستر، بلا إعادة ريندر):**
```bash
ffmpeg -i exports/MASTER_<ID>.mp4 \
  -c:v libx264 -preset slow -crf 21 -profile:v high -pix_fmt yuv420p \
  -maxrate 12M -bufsize 24M -x264-params keyint=60:min-keyint=30 \
  -movflags +faststart \
  -c:a aac -b:a 192k -ar 48000 -ac 2 \
  exports/…-VID-<slug>-v1.mp4
```

> `x264-params` **يرفض الأسماء الغلط بتحذير صامت** — الأسماء الصحيحة `keyint`, `min-keyint`, `rc-lookahead`, `frame-threads`. اطبع الأمر وتحقق من الحجم بعده، لا تفترض أنه طُبِّق.

## 2.5) جهّز ffmpeg مرة واحدة (الذهبي: لا تفترض وجوده)

```bash
python3 -m venv /tmp/venv2 && /tmp/venv2/bin/pip install imageio-ffmpeg numpy pillow
export FFMPEG=$(/tmp/venv2/bin/python -c "import imageio_ffmpeg as f; print(f.get_ffmpeg_exe())")
"$FFMPEG" -version | head -1     # 7.0.2-static
```

المستودع لا يشحن ffmpeg (حجمه ~80MB) — لكن **غيابه ليس عذرًا** لعدم القياس: `imageio-ffmpeg` يجيب ثنائيًا ثابتًا في ثوانٍ. لو تعذّر كل ذلك، يُكتب في التقرير `غير مقيس` صريحًا، ولا يُدَّعى قياس.

> **مصيدة loudnorm:** بعد `loudnorm` يخرج الصوت **96kHz** لا 48k. أضف `-ar 48000` بعده دائمًا؛ `qc_media.py` يعطي `FAIL` على أي معدل ≠ 48k.

## 3) فحوص ما بعد التصدير (على الملف المسلَّم نفسه)

**التنفيذ الآلي للصفوف 1–4 و7 (سكربت واحد):**

```bash
python3 scripts/qc_media.py exports/…-VID-<slug>-v1.mp4 \
  --aspect 9x16 --frames 6 --report reports/QC_MEDIA_<ID>.md
# exit 0 = يمر · exit 1 = مخالفة واحدة على الأقل (التقرير يسمّيها)
```

يعيد: المدة/الفريمات/الأبعاد/fps · `+faststart` (موضع `moov` أمام `mdat` من الـheader مباشرة) · LUFS/LRA/TP عبر `ebur128` · `blackdetect` · `freezedetect` · سلامة الفك · معدل عينة الصوت · لقطات إطارات للمعاينة. الصفوف 5–6 تبقى بصرية/يدوية.

| # | الفحص | الأمر | القبول |
|---|---|---|---|
| 1 | المدة/الفريمات/الأبعاد | `ffprobe -v error -show_entries stream=width,height,r_frame_rate,nb_frames,duration -of json` | `dur ±0.01` · `frames = dur×fps` |
| 2 | الحاوية والبتريت | نفس الأمر + `format=size,bit_rate` | yuv420p · حجم داخل السقف |
| 3 | الصوت | `ffmpeg -i f.mp4 -af ebur128=peak=true -f null -` | I −14±1 · TP ≤ −1.0 · **LRA ≤ 8** |
| 4 | أسود/تجميد | `blackdetect=d=0.1:pix_th=0.10` + `freezedetect=n=0.003:d=1` | صفر black · تجميد مقصود فقط |
| 5 | مناطق الأمان | `qc_safe` (أو عيّنات بصرية) | صفر بكسل في منطقة محجوزة |
| 6 | **حِدّة النص بعد الترميز** | فرق متوسط على قناع `lum>170` **خارج لحظة الترويسة** | ≥ 0.8× المرجع |
| 7 | سلامة الفك | `-f null -` | صفر decode error |
| 8 | ثبات الصوت (لو الصورة تغيّرت فقط) | `-c:a copy` لا إعادة مكس | نفس البصمة الصوتية |

> **مصيدة قياس:** قياس الحدة على لحظة الترويسة (نص كبير على خلفية نظيفة) يعطي رقماً مضلِّلاً — اقصر القياس على إطار فيه كابشن عادي.

## 4) كيف نعتمد crf 21 عندنا (بروتوكول قرار)

1. اختر 60 ثانية **من أكثر مشهد عندك ازدحامًا بالنص**.
2. صدّرها مرتين: `-crf 18` و `-crf 21` بنفس كل شيء آخر.
3. سجّل: الحجم · الحدة على قناع `lum>170` · هل يوجد banding في التدرّجات.
4. القرار: ننتقل إلى 21 لمفات المنصّة فقط إذا **الحدة ≥ 0.85×** والحجم أقل 30%+ بلا banding.
5. اكتب النتيجة في السجل بصيغة `{الرقم} — {المصدر} — {التاريخ} — مقيس`.

**حتى تُكتب النتيجة:** الماستر يبقى 18، وملف المنصّة 21 (لأنه لا يمسّ الماستر؛ الخسارة قابلة للتراجع).

## 5) سقوف الحجم والتنظيف

| البند | الحد |
|---|---|
| ملف منصّة 1080p (≤3 دقائق) | ≤ 45MB |
| ماستر 4K | بلا سقف — على Drive |
| مجلد تسليم واحد | تذكّر أن المساحة قد ترمي الملفات بلا تحذير ⇒ **`ls -la` في بداية ونهاية كل جلسة** |
| بعد التسليم | احذف `_build/` والشرائح الوسيطة · **لا تحتفظ بـ`_OLD`** |

**سلّم دائمًا `preview_720p.mp4`** مع الماستر: يفتح فورًا على أي جهاز، ويُستخدم للمراجعة بدل تحميل 4K.

## 6) بيئة الترميز

- ffmpeg ليس بالضرورة نظاميًا: `pip install imageio-ffmpeg` ثم
  `FF=$(python3 -c "import imageio_ffmpeg as f; print(f.get_ffmpeg_exe())")` — **افحص الدالة لا `command -v`**.
- الترميز الطويل في أمر واحد قد يستهلك الذاكرة ⇒ شرائح 9 ثوانٍ ثم `concat -c:v copy` ثم mux.
- للعمليات الطويلة: `start_process`/`nohup` — لا تحاصر الـshell.
